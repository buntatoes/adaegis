# 0.4

0.3.x made the three existing features hold together: network blocking, optional page cleanup, and the YouTube experiment. 0.4 should add the controls you need once you actually live with it, and close a few YouTube holes that are not more click-through patches.

This file is the working list for the 0.4 testing branch. Nothing here is committed as product behavior until it is implemented and tested.

## Keep

- No account, telemetry, remote filter list, or auto-update
- Network blocking does not need page access
- Page cleanup and YouTube stay opt-in, with the same permission prompts
- Exact-hostname exceptions, not suffix matching
- YouTube still does not rewrite streams, signatures, DRM, or playability
- Desktop Chrome / Chromium 120+, loaded unpacked from GitHub

## Proposed for 0.4.0

These are the ones worth building first. They fit the current popup and settings model.

### Exception list

Today you can only toggle the hostname of the active tab. After a few exceptions there is no way to see or delete them without visiting each site.

Add a list in the popup. Remove an entry from there. Optionally type a hostname to add one. Cap stays 200. Still exact hostnames only.

### Timed pause

Pause is on or off until you flip it again. A common case is “let this page load ads for ten minutes.”

Add 10 minutes, 1 hour, and until I turn it back on. Use `chrome.alarms` so it still fires after the service worker sleeps. The toolbar badge should show that protection is paused, not a blank OFF forever.

### Next video after a YouTube give-up

Playback errors, a 15-second stall, or the DOM scan cap currently stay off until a full reload, including after in-page navigation. Clicking another video should start a fresh budget for that video, not inherit a failure from the last one.

Turning the experiment off in the popup still stops it. Account and billing URLs still stay untouched.

### YouTube Music

`music.youtube.com` is not in the host list. The player JSON is close to watch; skip controls are not identical. Treat it as its own allowed host, with the same conservative edits (`adPlacements`, `playerAds`, `adSlots`) and a Music-specific skip selector if one exists. Do not grant Music access when someone only enables www YouTube.

### Player replies that are not `response.json()`

The fetch hook only replaces `response.json()`. If InnerTube reads `text()` and parses it, or still uses XHR on some navigations, 0.3.4 misses that body.

Hook `text()` on the same same-origin `/player` and `/get_watch` responses. Add XHR only if tests show YouTube still uses it for those two paths. Do not wrap every request.

## Later in 0.4.x

Useful, but they can wait if 0.4.0 should stay small.

| Idea | Why | Watch-outs |
| --- | --- | --- |
| Blocked-on-this-tab count | Badge is a global network-action counter. The popup never says what happened on this page. | Needs `declarativeNetRequestFeedback`. Keep it local; do not log hosts to disk. |
| Keyboard pause | `chrome.commands` so pause does not require the popup. | Ship with no default key, or a documented one people can change under `chrome://extensions/shortcuts`. |
| Custom block hosts | User-typed extra ad-tech hosts, stored locally, applied as dynamic DNR rules. The honest answer to “block this too” without EasyList. | Cap (for example 50). Exact hostnames. Never YouTube or `googlevideo.com`. |
| Settings export / import | A JSON file in the popup. Matches “everything stays on this computer.” | Validate on import the same way `normalize()` does now. No downloads permission if an `<a download>` blob is enough. |
| ping / beacon on bundled rules | Trackers often use those types; the 24 hosts currently cover script, image, XHR, and sub_frame only. | Re-test a few news sites before adding `media`. |
| A few more bundled hosts | Same style as 0.3.2: well-known ad-tech only (`adnxs.net`, Moat, BidSwitch, and similar). | No Facebook, Google site hosts, or YouTube media. |
| Cosmetic leftovers | Sticky GPT slots and a couple of obvious in-feed YouTube units that the current selectors miss. | Selectors stay specific. No generic `#ad` / `.ads`. |

## Not 0.4

- Remote lists, EasyList, or a filter-list updater
- Checking GitHub for a new ZIP from the extension
- Chrome Web Store listing
- Firefox / Android
- An element picker
- Spoofing ad-complete events, skipping unskippable ads by seeking, or touching stream URLs
- Per-site cosmetic-only vs network-only exceptions (the current exception is already “this whole page”)
- Broadening YouTube into `/embed` or `youtube-nocookie`

## Suggested order on this branch

1. Exception list in the popup (settings plumbing is already there)
2. Timed pause
3. Reset YouTube give-up when the video ID changes
4. `response.text()` on the existing player paths
5. YouTube Music
6. Then pick from the 0.4.x table

Version numbers stay at 0.3.4 until the first 0.4 feature is actually in the build.
